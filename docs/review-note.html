학습 문서 목록

오답노트는 어떻게 저장되고 다시 보는가

ROI 채점(POST /learning/roi-grade)을 할 때마다 풀이 기록이 review_node 테이블에 쌓입니다. 학습자는 이 기록 중 오답·부분정답을 오답노트로 보고, 같은 문제를 다시 풉니다. 결과는 학습용 보조이며 진단이 아닙니다.

화면흐름도의 "오답노트(목록) → 오답 상세 → 다시 풀기"에 맞춘 API입니다. 화면은 학습자 Vue 프로젝트가 맡습니다.

지금은 화면이 보낸 user_idx를 그대로 믿습니다. 로그인 세션으로 사용자를 서버가 판단하는 방식은 아직 없습니다.

주소

주소받는 값돌려주는 것
GET /learning/reviewsuser_idx(필수), solution(예: W,H, all, 기본 W,H), limit(1~200, 기본 50)본인 기록 최신순. 문제 부위·영상 종류, review_node.rn_disease, 결과 코드, 제출 그림 주소, 제출 시각
GET /learning/reviews/{번호}user_idx(필수)위 항목 + problem(다시 풀 문제. 정답 병명 없음). 문제가 지워졌으면 problem은 null. 남의 기록이면 404
GET /learning/problem/{문제번호}-문제 1건(정답 병명 없음). 삭제·비활성 문제는 404

파일별 역할

repositories/reviewNodeRepositories.py

한 줄로
본인 기록 목록(list_for_user)과 1건(get_for_user)을 문제와 함께 조회합니다.
하지 않는 일
다른 회원의 기록이나 지워진 기록(del_yn='Y')을 돌려주지 않습니다.

services/reviewNodeServices.py

한 줄로
채점 기록 저장, 오답노트 목록·상세를 화면용 모양으로 만듭니다.
하는 것
solution 값을 코드 목록으로 바꾸고(parse_solutions), 제출 그림 경로를 NAS 공개 주소로 바꿉니다.
헷갈리기 쉬운 점
목록의 병명은 문제 등록명(st_disease)이 아니라 그 풀이의 rn_disease입니다. rn_disease가 비어 있을 때만 문제 병명을 씁니다. 문제를 처음 받을 때는 정답을 숨깁니다.

services/learningServices.py 의 get_problem

한 줄로
문제 번호로 활성 문제 1건을 찾습니다. "다시 풀기"에 씁니다.
헷갈리기 쉬운 점
무작위 문제(/learning/problem)는 이미 푼 문제를 빼지만, 이 주소는 번호로 직접 받으므로 이미 푼 문제도 다시 받을 수 있습니다.

NAS가 안 될 때

  • 예전에는 NAS가 꺼져 있거나 업로드에 실패하면 채점 결과도, 기록도 남지 않고 오류(503·502)만 났습니다.
  • 이제는 기록을 그대로 남기고 그림 경로만 비웁니다. 채점 응답에 image_saved=false와 image_error(이유)가 들어갑니다.
  • NAS 오류의 자세한 내용은 서버 로그에만 남기고 응답에는 넣지 않습니다.
  • 관리자 리뷰 목록은 그림이 없는 기록을 "-"로 보여 줍니다.

아직 없는 것

  • 겹침 점수(IoU)·내가 그린 좌표·슬라이스 번호는 DB에 칸이 없어 저장하지 않습니다. 제출 그림 안에만 남습니다. 칸 추가는 팀 결정이 필요합니다.
  • 학습자가 오답노트에서 기록을 지우는 기능은 없습니다.

검증

pytest tests/test_review_notes.py는 가짜 DB와 NAS 대역으로 목록 필터·정렬, 남의 기록 차단, 다시 풀기의 정답 숨김, NAS 꺼짐·실패 때도 기록이 남는지, 채점 직후 오답노트에 나오는지를 확인합니다.
