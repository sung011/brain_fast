학습 문서 목록 · 무릎 MRI 분석

넘기며 분석의 '앙상블(B+v4)' 점수는 무엇을 하는가

화면 공유로 모은 무릎 MRI 여러 장을 기존 B 모델과 v4 모델에 같이 넣고, 두 점수를 미리 정해 둔 식으로 합쳐 학습용 참고 점수 하나를 보여 줍니다.

이 점수는 손상 확률이 아니고 의료 진단도 아닙니다. 두 모델을 합치는 식과 비중은 사전에 고정했고, 참고선은 보정 자료 181건에서 정했습니다. 시험 자료 181건은 이미 여러 번 사용한 자료로, 고정 뒤 탐색적으로 감사했으며 재표집의 오탐·놓침 변화 구간이 0을 포함해 개선은 확정되지 않았습니다. 다른 병원 자료(MRNet)에서는 기존 B보다 오탐이 늘었습니다(39건 → 118건). 화면 캡처 입력에서의 정확도는 확인하지 않았습니다.

켜고 끄기

  • 서버는 실행 창에 KNEE_SCROLL_ENSEMBLE_ENABLED=1 을 준 경우에만 앙상블 요청을 받습니다(.env 파일은 보지 않음). API 에서 scroll_score_mode 를 빼면 예전처럼 기존 B 로 처리합니다.
  • 모델 파일은 KNEE_SCROLL_LOCAL_BUNDLE_DIR 가 가리키는 로컬 묶음 폴더에서만 읽습니다. 묶음에는 B·v4·YOLO 세 파일과 knee_scroll_ensemble_bundle.json 이 들어 있고, 서버는 세 파일의 크기·지문(SHA-256)을 코드에 적힌 값과 비교해 다르면 쓰지 않습니다.
  • 화면에서 무릎은 넘기며 분석 하나로 판독하며, 점수의 기본은 앙상블(B+v4)입니다. '기존 B'는 비상 복귀용으로만 남겨 두었고, 바꾸면 이전 결과·참고선·해설·그림이 바로 지워집니다.
  • 화면은 처음 열릴 때 GET /api/v1/knee/screen-analysis/config 로 앙상블 사용 가능 여부만 묻습니다. 서버가 기존 B 전용으로 켜져 있으면 앙상블 항목을 '이 서버에서 꺼짐'으로 표시하고 '기존 B'를 고른 뒤 그 이유를 보여 줍니다(몰래 바꾸지 않음).
  • 앙상블은 여러 장을 함께 보는 모델이라, 무릎의 한 장 판독('선택 영역 분석')은 화면에서 제공하지 않습니다(버튼 숨김). 뇌 CT 의 '선택 영역 분석'은 그대로입니다.

파일별 역할

class/knee/scroll_ensemble.py

한 줄 요약
같은 15장으로 B와 v4 점수를 구해 고정 식으로 합친다.
받는 것
서버가 디코드하고 같은 화면을 뺀 고유 장 목록(15~20장).
하는 일
가운데 15장을 고른다 → 장마다 ACL 위치 모델(YOLO)로 상자를 찾는다 → 상자보다 1.5배 큰 정사각형으로 잘라 v4에 넣는다 → 같은 15장을 B에 넣는다 → 두 원 점수(logit)를 각자 기준선 중심으로 맞춘 뒤 0.5:0.5 로 합친다.
돌려주는 것
합친 참고 점수와 고정 참고선(47.99점)보다 위/아래, 장별 검출 상태. 크롭이 3장보다 적으면 점수 없이 '미분석'.
하지 않는 일
장을 반복·보간해 15장을 채우기, 다른 장 상자 빌려 쓰기, 시연 결과를 보고 식·참고선 바꾸기, Grad-CAM 그리기, 재학습.
헷갈리기 쉬운 점
미분석일 때 기존 B 점수를 대신 보여 주지 않습니다. B 점수가 필요하면 사용자가 '기존 B'를 골라 새로 분석합니다.

class/knee/acl_volume.py (기존 B)

바뀐 것
로컬 묶음이 설정되면 그 B 파일만 읽습니다(지문 확인). 앙상블용으로 반올림 전 원 점수(logit)를 주는 logit() 을 추가했습니다.
그대로인 것
기존 B 분석 결과와 응답 의미.

class/knee/screen_localization.py (ACL 위치 모델)

바뀐 것
같은 YOLO 인스턴스로 v4 입력용 detect_raw() 를 추가했습니다. 화면 표시용 좌표(소수 4자리)가 아니라 반올림 전 원 좌표를 검사해서 씁니다. 두 기능 모두 CPU 로 추론합니다.
헷갈리기 쉬운 점
앙상블 화면의 상자는 'v4 입력 크롭을 만든 위치 참고'입니다. 병변 위치나 점수의 원인이 아닙니다.

routers/kneeScreenAnalysis.py, class/knee/scroll_analysis.py

받는 것
기존 요청 + 선택 항목 scroll_score_mode(legacy 또는 ensemble, 없으면 legacy).
돌려주는 것
앙상블이면 score_mode·runtime_profile_id·ensemble 정보가 붙은 응답. 고유 10~14장이나 크롭 부족은 HTTP 200 '미분석'(점수 null). 서버가 앙상블을 켜지 않았으면 503, 한 장 분석·영상 일부 범위는 422, 모델 파일 문제는 503.
그대로인 것
주소, 장 수·크기 한도, 한 번에 한 계산(실행권), 시간 제한 60초, 한 장 분석.

templates/screen_analyze.html, assets/js/screen-result-adapter.js

하는 일
점수 모델 선택, 앙상블 결과를 'xx.x점'(% 아님)·참고선 47.99점·주의 문구로 표시, 미분석이면 이유만 표시.
헷갈리기 쉬운 점
모드를 바꿔도 이미 서버에서 돌고 있는 계산은 멈추지 않습니다. 그 계산이 끝나기 전 새 요청은 '분석 중'(429)으로 안내됩니다.

로컬 실행 예 (팀장님 노트북 시연용)

모델 묶음 폴더 경로는 각자 PC 에 맞게 바꿉니다. 서버는 이 PC 안에서만(127.0.0.1) 엽니다.

앙상블 켜기(PowerShell)
$env:KNEE_SCROLL_LOCAL_BUNDLE_DIR = "D:\시연\knee_scroll_ensemble_bundle_r1"
$env:KNEE_SCROLL_ENSEMBLE_ENABLED = "1"
$env:KNEE_SCREEN_LOCALIZATION_ENABLED = "1"
python -m uvicorn main:app --host 127.0.0.1 --port 8000 --workers 1

기존 B 전용(비상 복귀) — 앙상블을 끄고 v4 를 읽지 않음
$env:KNEE_SCROLL_LOCAL_BUNDLE_DIR = "D:\시연\knee_scroll_ensemble_bundle_r1"
$env:KNEE_SCROLL_ENSEMBLE_ENABLED = "0"
python -m uvicorn main:app --host 127.0.0.1 --port 8000 --workers 1

첫 분석은 모델을 처음 읽느라 느립니다. 발표 전에 한 번 미리 분석해 두세요.
