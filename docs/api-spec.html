학습 문서 목록

학습자 화면(Vue)이 쓰는 API

프론트 담당이 이 문서만 보고 화면을 붙일 수 있게, 주소·보내는 값·돌아오는 값·오류를 한곳에 모았습니다. 실제로 호출해 보려면 서버를 켜고 /docs(FastAPI 자동 문서)를 열면 됩니다.

공통 규칙

  • 성공하면 대부분 {"ok": true, ...}입니다. 실패하면 {"detail": "한국어 메시지"}이고, 화면에는 detail을 그대로 보여 주면 됩니다.
  • 입력 형식이 틀리면 422, 조건이 맞지 않으면 400, 없으면 404, 모델이 아직 없으면 503입니다.
  • 부위 st_part: 1=뇌, 2=흉부, 3=복부, 4=무릎 (영문 brain, chest… 도 받음). 영상 st_modal: 1=X-ray, 2=CT, 3=MRI (xray, ct, mri 도 받음).
  • 지금은 로그인 후 받은 idx를 화면이 user_idx로 보냅니다. 세션 방식으로 바꿀지는 팀 회의 안건입니다.
  • 분석·채점 결과는 학습용 보조이고 진단이 아닙니다. 응답의 disclaimer 문구를 화면에 함께 보여 줍니다.

1. 로그인

POST/login

보내는 값(JSON): user_id, user_pw

성공: {"ok": true, "idx": 3, "user_id": "...", "user_name": "...", "mb_level": 1}

실패 401: "아이디 또는 비밀번호가 올바르지 않습니다." — 어느 쪽이 틀렸는지는 일부러 알려 주지 않습니다.

2. 아이디·비밀번호 찾기

POST/find-id

보내는 값: user_name(1~10자), user_birth(YYYY-MM-DD)

성공: {"ok": true, "user_id": "le***@example.com", "user_ids": [...]} — 아이디는 앞 두 글자만 보이게 가립니다. 여러 개면 user_id는 null이고 user_ids를 봅니다.

오류: 404 일치하는 회원 없음, 429 짧은 시간에 너무 많이 시도함(10분 기준).

POST/find-pw/verify → /find-pw

1단계 verify: user_name, user_birth, user_id(최대 30자)로 본인 확인. 성공하면 {"ok": true}.

2단계 find-pw: 위 세 값 + user_pw, user_pw_confirm(4~72자). 성공하면 {"ok": true, "message": "비밀번호가 변경되었습니다."}.

오류: 400 두 비밀번호 불일치 등, 404, 429.

3. 문제 받기

GET/learning/problem?st_part=2&st_modal=1&user_idx=3

조건에 맞는 문제 1개를 무작위로 줍니다. user_idx를 주면 이미 푼 문제는 빼고 고릅니다.

성공: {"ok": true, "problem": {"idx": 12, "st_part": "2", "st_modal": "1", "st_image": "/stylesheets/..."}} — 정답 병명은 들어 있지 않습니다.

404: 풀 문제가 더 없음.

GET/learning/problem/{study_idx}

번호로 문제 1개. 오답노트의 "다시 풀기"에 씁니다. 삭제된 문제면 404.

GET/learning/problem/{study_idx}/image

문제 영상 파일 자체를 돌려줍니다(PNG 등). 서버가 NAS에서 대신 받아 주므로 CORS 걱정 없이 <img src>에 바로 쓰거나, 받아서 그대로 채점에 올리면 됩니다. MRI는 ?slice_index=0처럼 장 번호를 붙입니다.

오류: 404 문제 없음, 502 NAS에서 못 받음.

필드필수설명

roi_type예box 또는 circle
x, y, width, heightbox면왼쪽 위 좌표와 크기
cx, cy, radiuscircle이면원 중심과 반지름

study_idx, user_idx권장있으면 풀이 기록이 남고 오답노트에 들어갑니다

필드뜻
targets의심 부위 목록. 하나마다 x, y, width, height(0~1), findings(소견 이름들), confidence, found(찾음), near(근처), iou, recall
target_count, found_count"의심 부위 N곳 중 M곳을 찾았습니다"에 씀

오류: 400 좌표·rois 형식 오류, 503 그 부위 모델이 아직 서버에 없음, 502 기록 저장 실패.

5. 병명 제출

POST/learning/submit

보내는 값(JSON): study_idx, answer(병명), st_part, st_modal, exclude_idxs, user_idx

성공: {"ok": true, "correct": true, "expected": "흉막삼출", "next": {...} | null, ...}

6. 오답노트

GET/learning/reviews?user_idx=3&solution=W,H

내 풀이 목록(최신순). solution: C정답·H부분정답·W오답을 쉼표로, all이면 전부. 기본 W,H. limit 기본 50(최대 200).

항목: review_idx, study_idx, st_part/st_part_label, st_modal/st_modal_label, disease, solution/solution_label, image_url(내 ROI가 그려진 제출 이미지), created_at

GET/learning/reviews/{review_idx}?user_idx=3

위 항목 + problem(다시 풀 수 있으면 문제 정보, 삭제된 문제면 null → "다시 풀기" 비활성). 다른 사람 기록이면 404.

7. 화면 공유 분석 (흉부)

GET/api/v1/thorax/health

status(ok/degraded), models_loaded, models_error. 흉부 모델은 첫 요청 때 불러오므로 처음에는 degraded가 정상입니다.

POST/api/v1/thorax/analyze/screen-roi (multipart)

보내는 값: image(최대 5MB), modality, include_overlay

응답은 뇌 CT /api/v1/analyze/screen-roi와 같은 모양입니다: classification.findings(소견별 점수), overlay_png_base64, overlay_summary(예: "흉막삼출: 하부-환자 우측 0.28"), disclaimer, latency_ms.

헷갈리기 쉬운 점: 흉부 점수는 확률(%)이 아니라 그 소견 박스의 가장 높은 신뢰도입니다. 0.3도 "찾았다"는 뜻입니다. 좌우는 환자 기준(화면 왼쪽 = 환자 오른쪽)입니다. 흉부 판독문(/explain)은 아직 없습니다.

오류: 413 너무 큼, 400 이미지가 아님, 503 모델 준비 중.

이 문서가 다루지 않는 것

  • 관리자(/admin) 주소. 관리자 화면은 서버가 직접 HTML을 그립니다.
  • 팝업·Q&A·용어 사전 등 흉부와 관계없는 학습자 API. 서버 /docs에서 확인합니다.
  • 서버 설정. 흉부 모델 서버 설정을 보세요.
