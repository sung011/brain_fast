# 10월 프로젝트 점검 정리

11월 4일 발표용이다. 평가표 항목 순서로, 지금 코드와 `docs/`에서 말할 수 있는 내용만 적었다. 정확도 숫자는 저장소에 없어서 넣지 않았다.

계획서 원문은 저장소에 없다. 아래 “계획”은 코드와 `docs/`가 맡은 범위다.

## MVP 범위 대비 구현 현황 (10점)

| 구분 | 기능 |
|---|---|
| 완료 | 뇌 CT 화면 분석, 학습 문제·병명 채점, ROI 채점, 오늘 학습 현황·오답·기록, 관리자 회원·스터디·팝업·Q&A·리뷰, Object Storage 저장 |
| 부분 | MRI는 문제 등록과 슬라이스 선택까지 되고, MRI 전용 분석 모델은 없음 |
| 미구현 | 흉부, 복부, 무릎, 뇌 MRI 분석 패키지. `docs/index.html`에 추가 예정으로만 적혀 있음 |

완료는 학습 루프와 뇌 CT 분석이다. 다른 부위 분석은 이후 범위다.

## 핵심 기능 구현 수준 (15점)

서비스 목적은 학습자가 영상을 풀고, 그 결과가 관리자에게 남는 것이다. 이 목적에 필요한 흐름은 연결되어 있다.

- 관리자가 문제를 등록하면 이미지가 Object Storage에 올라가고 `study` 행이 생긴다.
- 학습자는 문제 1건을 받고, 제출 전에는 정답 병명을 받지 않는다.
- 병명 제출은 DB 정답과 비교한다. ROI 제출은 모델이 표시한 영역과 겹침으로 정답·부분정답·오답을 낸다.
- 채점 이미지와 기록이 저장되고, 오늘 학습 시간·문제 수·정답률을 부위별로 돌려준다.
- 관리자 목록은 SSE로 갱신된다.

## 대표 시나리오 동작 (15점)

대표 시나리오는 뇌 CT 문제의 ROI 제출이다. 처음 등록부터 관리자 확인까지 한 줄로 이어진다.

1. `/admin/study/create`에서 뇌 CT 문제를 등록한다.
2. 학습자가 문제 1건을 받는다.
3. 박스 또는 원을 그려 `/learning/roi-grade`로 제출한다.
4. 정답·부분정답·오답과 색 overlay가 나온다.
5. 채점 이미지가 저장되고 관리자 리뷰 목록이 갱신된다.
6. `/learning/today`에서 오늘 문제 수와 정답률을 확인한다.

시간이 남으면 `/`에서 같은 영상의 출혈 점수, overlay, 한국어 설명을 이어서 보여 준다.

## 시연 결과 확인 (10점)

입력과 결과를 화면에 같이 두면 된다.

| 입력 | 확인할 결과 |
|---|---|
| 문제 이미지 파일 | Object Storage 경로, `study` 목록에 1건 |
| ROI 좌표 | 판정 문구, IoU·포함률, overlay 이미지 |
| 같은 사용자로 오늘 조회 | 부위별 문제 수·정답률 |
| 관리자 리뷰 화면 | 방금 제출이 목록에 추가 |

시연 전에 DB, Object Storage, Hugging Face 가중치 다운로드를 확인해 둔다. 모델은 첫 요청 때 불러와서 첫 실행이 느리다. 발표 직전에 한 번 실행해 두면 된다.

## AI 기능 적용 (10점)

AI는 화면 분석과 ROI 채점 안에 실제로 호출된다.

- 분류: 출혈 6클래스와 생식세포종을 ConvNeXt-Base와 EfficientNetV2-M 평균으로 추정한다.
- 위치: Grad-CAM으로 모델이 본 영역을 색칠하고, 그 영역을 ROI 채점 기준으로 쓴다.
- 문장: MedGemma 1.5 4B가 한국어 설명을 만든다. API를 쓸 수 없으면 점수 요약 문장으로 바뀐다.

병명 채점은 AI가 아니다. DB에 저장한 정답 문자열과 비교한다.

## AI 결과 검증 (10점)

| 검증 | 하는 일 | 한계 |
|---|---|---|
| pytest | 학습 현황, 팝업, MRI 슬라이드 등록, 슬라이스 선택, 저장 경로 | 모델 정확도는 측정하지 않음 |
| ROI 규칙 | IoU, 포함률, 중심 거리로 정답·부분정답·오답 | 기준 영역은 의사 표시가 아니라 모델 마스크 |
| 안내 문구 | 결과가 학습 보조이고 최종 판단은 의사에게 있음 | 임상 민감도·특이도 숫자는 저장소에 없음 |

발표에서는 규칙이 코드에 있다는 점까지만 말하고, 성능 숫자는 만들지 않는다.

## 주요 변경 사항 기록·정합성 (10점)

설계와 코드가 맞다. 요청 순서는 `AGENTS.md`와 `docs/폴더구조_초보자가이드.md`에 있고, 기능 설명은 `docs/` HTML에 있다.

코드에 남아 있는 변경은 다음과 같다.

- 분석은 `class/brain/`만 두고, 다른 부위는 같은 파일 역할로 나중에 넣게 되어 있다.
- 학습 등록은 파일마다 문제가 기본이고, 한 문제의 슬라이드는 MRI만 가능하다.
- ROI 채점은 CT 한 장과 MRI 슬라이스 지정을 같은 API에서 받는다.
- 판독문은 API, 로컬 모델, 점수 요약 문장 세 갈래다.
- 이미지는 네이버 클라우드 Object Storage에 올리고 DB에는 공개 경로만 저장한다.

날짜별 변경 일지는 저장소에 없다. 멘토 회의에서 바뀐 항목이 있으면 이 칸에 이유와 함께 한 줄씩 넣으면 된다.

## 이슈 대응·피드백 의사결정 (10점)

| 이슈 | 원인 | 지금 대응 | 남은 판단 |
|---|---|---|---|
| 다른 부위 분석이 없음 | 분석 패키지가 뇌 CT만 있음 | 등록·풀이는 부위 값을 받아 둠 | 다음 마일스톤에 패키지를 추가 |
| ROI 정답이 모델 마스크 | DB에 의사 표시 영역이 없음 | 겹침 규칙으로 학습 채점을 우선 동작 | 문제별 정답 영역을 저장해 비교 |
| 첫 분석이 느림 | 서버 시작 때 모델을 기본으로 안 불러옴 | 시연 전에 한 번 실행 | 운영에서는 시작 시 로드 |
| 설명 문장이 외부 API에 의존 | MedGemma 기본값이 API | 실패 시 점수 요약 문장 | 시연은 요약 문장으로도 끊기지 않게 유지 |
| 로그인 응답에 개발용 비밀번호 확인 값이 있음 | 확인용 응답이 남아 있음 | 시연 전에 제거 필요 | 발표 화면에는 두면 안 됨 |

학습자 API는 세션 대신 `user_idx`를 받는다. 학습 기록은 동작하고, 본인 확인은 이후 세션으로 바꾸는 판단이 맞다.

## 구현 결과 설명·전달 (10점)

발표에서 이 네 문장을 먼저 말하면 항목이 닫힌다.

- MVP는 학습 등록, 풀이, ROI 채점, 기록, 관리자 확인까지이고 뇌 CT 분석이 포함된다.
- 핵심 기능은 그 흐름이 화면에서 끝까지 이어진다는 점이다.
- AI는 분류, 위치 표시, 한국어 설명에 쓰이고, 병명 문자열 비교는 AI가 아니다.
- 시연 결과는 판정 문구, overlay, 저장된 리뷰, 오늘 학습 수치로 확인한다. 임상 성능 숫자는 아직 없다.
