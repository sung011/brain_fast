학습 문서 목록

회원가입 화면은 무엇을 하는가

학습자가 이메일·비밀번호와 닉네임·생년월일·학교·전공을 입력하는 화면입니다. 지금은 화면만 있습니다. 입력한 값은 서버로 보내지도, 저장되지도 않습니다.

이 화면에는 실제 가입 API가 연결되어 있지 않습니다. 그래서 /signup 맨 위에는 입력하기 전부터 “화면 시연 · 실제 가입·전송·저장 없음 / 실제 개인정보는 입력하지 마세요” 안내가 계속 보입니다(1단계·2단계·JavaScript가 꺼진 화면 모두). 마지막 “회원가입” 버튼도 “준비되지 않았습니다”라는 안내만 보여 주고, 가입이 된 것처럼 보이는 완료 화면은 ?preview=1(설계 미리보기)에서만 나옵니다.

약관과 개인정보 안내는 위치와 동작을 확인하는 임시 문구입니다. 법적 효력이 있는 본문이 아닙니다. 서비스 화면에 나오는 AI 분석은 학습 참고자료이며 의료 진단이 아닙니다.

주소 두 가지

주소보이는 것
/signup입력·확인·오류 안내가 동작하는 화면. 맨 위에 “실제 가입 아님” 안내가 항상 있고, 완료 화면과 설계 도구는 없다.
/signup?preview=1위 화면에 설계 도구 막대(단계 이동, 이메일 중복·네트워크 오류 시뮬레이션)와 “가상 완료 화면”이 더해진다. 실제 계정 생성과 메일 발송은 하지 않는다.

입력 흐름

  1. 1단계 계정 정보: 이메일, 비밀번호, 비밀번호 확인, 약관 동의. 조건을 모두 채워야 “다음 단계”가 켜집니다.
  2. 2단계 기본 정보: 닉네임, 생년월일, 학교, 전공. 조건을 모두 채워야 “회원가입”이 켜집니다. “이전”으로 돌아가도 입력은 그대로 남습니다.
  3. 마지막: 운영 화면은 준비 중 안내, 미리보기는 가상 완료 화면.

templates/signup.html — 화면 뼈대

한 줄
입력칸과 안내 글, 약관 창의 구조를 정합니다.
받는 것
preview 값 하나.
하는 일
왼쪽 소개는 1단계(계정 정보)에서 제목·짧은 설명·직접 그린 스캔 프레임 그림·“살펴보기 → 비교하기 → 기록하기” 흐름만 두어 글자를 줄였습니다. 2단계(기본 정보)로 넘어가면(body의 data-stage 값이 2가 되면) 그림과 흐름 자리에 서비스 항목 네 가지(“영상 보고 문제 풀기 / 관심 영역 표시와 복습 / AI 참고 분석 / 용어 사전과 질문”)가 나타나고, “이전”으로 돌아가면 다시 그림이 나옵니다. 가입 완료 화면(3단계, ?preview=1에서만 존재)에서는 소개 제목·설명 자리에 환영 문구(“환영합니다! 나의 학습 노트를 시작해요.”)를 보여 1단계 소개가 반복되지 않게 하고, 흐름 문구는 숨깁니다. 즉 1단계는 간략 소개, 2단계는 세부 항목, 3단계는 환영 문구입니다. 이 항목은 저장소 AGENTS.md 기능 명세(학습 문제·병명 제출, ROI 채점과 리뷰 저장, 화면 공유 분석, 의학 용어 사전·Q&A)에 이미 있는 기능만 따랐고 새 기능을 약속하지 않으며, 문구는 팀이 확인해야 합니다. 창 높이가 860px 이하인 데스크톱에서는 한 화면에 맞추려고 설명 글을 접어 제목만 보이고, 휴대폰(700px 이하)에서는 폼이 밀리지 않도록 숨깁니다. 화면 바깥 빈 여백은 글자 없는 장식(.bg-deco: 궤도 원, 스캔 프레임, 점 격자, 옅은 민트 빛)으로 채웠고, 스크린리더에서는 숨깁니다. 글자 수 상한과 조건은 라벨 옆 작은 글씨(.lsuffix)로 항상 보입니다(이메일 “최대 30자”, 닉네임 “1~10자”, 학교 “한글·영문 · 최대 20자”, 전공 “기타는 직접 입력 · 최대 20자”, 생년월일 “만 14세 이상”). 입력칸이 상한(maxlength)에서 조용히 멈추기 때문에, 상한에 닿는 순간 그 글씨가 민트색으로 바뀌고 “· 한도 도달”이 덧붙어 멈춘 이유를 알립니다(줄을 새로 끼우지 않아 화면 높이는 변하지 않음). 한 글자를 지우면 원래대로 돌아옵니다. 자세한 힌트 문장은 데스크톱 압축 화면에서는 스크린리더 전용으로 남깁니다. 미리보기일 때만 설계 도구 막대와 완료 화면 구조를 넣고, 운영 화면일 때만 머리말 바로 아래에 “실제 가입 아님” 안내 띠(#demoNotice)를 넣습니다. 안내가 폼 밖 맨 위에 있어서 1·2단계 어디서나, 좁은 휴대폰 첫 화면에서도, 스크립트가 꺼져도 보입니다. 모든 입력칸에 label을 이어 두었고, 오류 문구는 스크린리더가 읽도록 aria-live로 표시합니다. 전공 선택칸과 직접 입력칸은 둘 다 aria-describedby로 안내(majorHint)와 오류(majorError)에 연결되어 있습니다.
돌려주는 것
HTML.
하지 않는 일
입력칸에 name 속성을 주지 않고 폼에 action도 없습니다. 스크립트가 늦게 로드되어도 이메일·비밀번호가 주소창(URL)이나 서버로 전송되지 않게 하려는 것입니다. 외부 글꼴·이미지·CDN도 쓰지 않습니다.
헷갈리기 쉬운 점
서버 필드 이름(user_id, user_pw, user_name, user_birth, user_un, user_sp)은 후속 가입 API를 만들 때 연결합니다. 비밀번호 확인과 동의는 서버 필드가 아직 없습니다.

assets/css/signup.css — 스타일

한 줄
검은 배경과 민트색 강조, 반응형 배치를 정합니다.
받는 것
없음.
하는 일
넓고 충분히 높은 화면(가로 981px 이상, 세로 700px 이상)은 스크롤 없이 한 화면에 들어오도록 압축합니다. 두 열을 가운데로 모아 간격을 좁히고, 가입 폼은 오른쪽 카드(테두리·둥근 모서리·그림자)로 만들어 소개와 구분합니다. 입력칸 높이와 간격은 창 높이(vh)에 맞춰 줄어들고, 이 화면에서는 폼의 보조 설명 문장을 숨깁니다. 세로 700px 미만이거나 가로 980px 이하인 화면은 압축하지 않고 페이지 전체가 일반 세로 스크롤을 씁니다. 카드 안 스크롤은 오류 문구가 여러 개 겹칠 때를 위한 안전장치일 뿐 평소에는 생기지 않습니다. 700px 이하 모바일은 웹 화면을 좁힌 모양이 아니라 “가입 폼이 맨 위에서 바로 시작하는” 별도 구성입니다. 큰 소개(위 문구·설명·그림·흐름)를 숨기고 한 줄 태그라인만 남기며, 안내 띠를 작게 줄이고, 폼 위 설명 문장을 숨기고, 가입 폼은 카드로 만듭니다. 조건은 데스크톱과 같이 라벨 옆 글씨와 “한도 도달” 강조로 보여 줍니다. 입력칸 글자는 16px 이상(iOS는 그보다 작으면 포커스 때 화면을 자동 확대함), 입력칸 높이 46px, 체크박스 20px로 터치하기 쉽게 했습니다. 390×844 화면에서 1단계·2단계 전체가 첫 화면에 들어오고(작은 폰은 1단계 버튼이 조금 아래에 있음), 320px에서도 가로 스크롤이 생기지 않게 긴 오류·이메일은 줄바꿈합니다. 701~980px 태블릿은 기존 두 열 구성을 씁니다.
돌려주는 것
스타일.
하지 않는 일
참고 사이트의 로고·문구·이미지를 쓰지 않습니다. 장식 그림은 직접 그린 추상 SVG이고 환자 영상이나 진단 표시가 없습니다.
헷갈리기 쉬운 점
관리자 화면의 styles.css, custom.css와 별개 파일이라 서로 영향을 주지 않습니다.

assets/js/signup.js — 동작

한 줄
입력을 검사하고, 단계를 옮기고, 오류를 보여 줍니다.
받는 것
화면에 입력한 값.
하는 일
  • 이메일: 30자 이하, 기본 형식, 공백 자동 제거.
  • 비밀번호: 8~64자, 영문·숫자·특수문자 포함, 공백 없음. 조건을 실시간 표시하고 “표시/숨김”은 비밀번호와 확인이 따로 동작합니다. 한글은 특수문자로 치지 않습니다.
  • 동의: 필수 셋(이용약관·개인정보·만 14세)이 모두 있어야 진행. 전체 동의와 일부 선택(중간 상태), 선택 항목(마케팅)은 거부해도 가입 가능.
  • 닉네임 1~10자, 앞뒤 공백을 뺀 뒤 빈 값이면 거부.
  • 학교 1~20자, 한글·영문만(공백과 . · ( ) -는 “서울대학교 (글로벌캠퍼스)” 같은 이름을 위해 허용). 숫자는 입력하는 즉시, 그 밖의 특수문자·이모지는 칸을 벗어날 때 이유와 함께 오류를 보여 주고 가입 버튼을 막습니다. 글자가 하나도 없는 값(예: ...)도 거부합니다. 제한: 이름에 숫자가 들어가는 학교(예: “제2고등학교”)도 막힙니다. 그런 이름을 허용하려면 이 규칙을 완화해야 합니다.
  • 전공: 목록에서 고르고, “기타 보건의료계열”이면 직접 입력칸이 나타나 필수(required)가 됩니다(최대 20자). 전공을 고르지 않은 채 칸을 벗어나거나, 직접 입력칸을 비우거나 공백만 넣고 벗어나면 오류 문구와 aria-invalid가 표시되고, 20자를 넘기면 바로 표시됩니다. 다른 전공을 고르면 직접 입력칸은 숨겨지고 그 오류도 지워집니다.
  • 생년월일: 실제 있는 날짜, 미래가 아님, 만 14세 이상.
  • 키보드: Enter로 현재 단계 진행, Esc로 약관 창 닫기, 닫으면 눌렀던 버튼으로 포커스 복귀.
  • 첫 진입: 마우스가 있는 기기에서는 이메일 칸에 바로 포커스합니다. 창이 좁아도 화면이 이메일 칸으로 스크롤되지 않게 해서 맨 위 안내가 가려지지 않습니다. 터치 기기는 키보드가 자동으로 열려 소개를 가리므로 포커스하지 않습니다(의도한 차이).
돌려주는 것
화면 변화만. 반환값이나 서버 요청은 없습니다.
하지 않는 일
fetch/XHR로 서버에 보내지 않고, console·localStorage·sessionStorage·쿠키·URL에 입력을 남기지 않습니다. 닉네임 중복 확인은 하지 않습니다(현재 서버가 같은 닉네임을 허용).
헷갈리기 쉬운 점
이메일 중복 검사는 미리보기에서만 “시뮬레이션”입니다. 실제 조회 API가 있다는 뜻이 아닙니다. 화면의 비밀번호 규칙(8~64자)은 현재 서버 검증(4~100자)보다 엄격하므로, 연결 때 서버와 통일해야 합니다.

tests/test_signup_page.py — 테스트

한 줄
화면과 스크립트가 약속을 지키는지 자동으로 확인합니다.
받는 것
없음.
하는 일
화면 응답, 필수 입력칸, 미리보기는 ?preview=1일 때만 켜지는지, 운영 화면 맨 위에 “실제 가입 아님” 안내가 폼보다 앞에 숨김 없이 있는지, 전공 칸이 오류 문구에 연결되어 있는지, CSS/JS가 서버에서 나오는지, 입력칸에 name이 없는지, 스크립트에 전송·저장 코드가 없는지, /admin/user/signup 등이 여전히 로그인 없이 열리지 않는지를 확인합니다. 돌려주는 것
통과/실패.

헷갈리기 쉬운 점

실제 가입을 연결하기 전에 정할 일

  • 공개 가입 API와 요청 형식(현재 관리자용 UserCreate는 관리자 세션 보호가 있어 그대로 쓸 수 없음).
  • 이메일 인증 정책, 약관·개인정보 본문·버전·시행일, 동의 이력 저장.
  • 비밀번호 정책 통일(서버 4~100자 ↔ 화면 8~64자). 한글 등 여러 바이트 문자가 들어가면 해시 라이브러리 길이 제한(72바이트)에 걸릴 수 있어 확인이 필요합니다.
