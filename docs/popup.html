팝업 등록과 목록 SSE

관리자가 홍보 팝업을 등록·수정·삭제하면, 열려 있는 팝업 목록이 새로고침 없이 다시 불러옵니다. 팝업은 학습자 메인 홍보용이고, 영상 분석이나 진단이 아닙니다.

목록 화면은 GET /admin/popups/stream 을 계속 열어 둡니다. 등록이 끝나면 서버가 popup_created 를 보내고, 목록 스크립트가 GET /admin/popups_all 로 표를 다시 그립니다.

파일마다 보기

routers/commonness.py — GET /popups
한 줄: 학습자 메인에 띄울 홍보 팝업만 돌려줍니다.
받음: 요청 본문 없음. 서버 시각으로 기간을 판단합니다.
함: 삭제되지 않았고 상태가 노출(N)이며, 지금이 노출 시작과 종료 사이인 행만 pp_sort 순으로 고릅니다. 시작이 비어 있으면 이미 시작된 것으로, 종료가 비어 있으면 종료가 없는 것으로 봅니다.
돌림: 번호, 제목, 이미지 경로와 공개 URL, 링크, 순서, 상태, 시작·종료 시각.
안 함: 숨김, 삭제, 시작 전, 종료 지난 팝업은 넣지 않습니다. 관리자 목록(GET /admin/popups_all)을 이 조건으로 줄이지 않습니다.
헷갈림: 노출이어도 기간 밖이면 빠집니다. 기간 안이어도 숨김이면 빠집니다. 두 조건을 같이 봐야 합니다.
utils/popup_sse.py
한 줄: 팝업 변경 알림을 구독자에게 전달하는 통로.
받음: 이벤트 이름과 JSON으로 보낼 수 있는 데이터.
함: 구독 큐에 메시지를 넣고, SSE 한 줄(event / data)로 바꿉니다.
돌림: 구독 큐, 또는 text/event-stream 본문.
안 함: DB 저장, 이미지 업로드, 목록 HTML.
헷갈림: 이 통로는 관리자 목록용입니다. 학습자 GET /popups 와는 별개입니다.
services/popupServices.py · repositories/popupRepositories.py
한 줄: 노출로 등록할 때 표시 순서를 다음 번호로 정합니다.
받음: 등록 값. 노출(state=N)이면 이미 저장된 노출 팝업의 가장 큰 pp_sort.
함: 노출 팝업이 있으면 그 최대값에 1을 더합니다. 없으면 0을 저장합니다. 숨김(state=S)은 화면에서 보낸 순서를 그대로 둡니다.
돌림: 저장된 팝업 행. 미리 보기는 GET /admin/popups/next-sort 의 pp_sort.
안 함: 이미 노출 중인 팝업의 순서를 다시 매기지 않습니다. 숨김 팝업은 다음 번호 계산에 넣지 않습니다.
헷갈림: 숫자가 작을수록 먼저 보입니다. 그래서 새 노출 팝업은 맨 뒤 번호가 됩니다.
routers/admin.py — POST /admin/popup, PUT, DELETE, GET /admin/popups/stream
한 줄: 팝업을 저장한 뒤 목록에 알리고, 스트림으로 그 알림을 흘려보냅니다.
받음: 등록은 이미지 파일과 제목·링크·순서·기간·상태. 스트림은 관리자 세션.
함: 등록 성공 후 popup_created, 수정 후 popup_updated, 삭제 후 popup_deleted 를 보냅니다. 스트림은 연결 직후 connected 를 보내고 30초마다 keepalive 를 넣습니다.
돌림: 등록·수정은 저장된 팝업 정보. 삭제는 idx. 스트림은 이벤트 줄.
안 함: 저장에 실패하면 이벤트를 보내지 않습니다. 학습자 공개 목록을 이 스트림으로 바꾸지 않습니다.
헷갈림: /admin/popups/stream 은 /admin/popups/{idx} 보다 먼저 등록되어 있습니다. 숫자 idx 조회와 주소가 겹치지 않게 하기 위해서입니다.
assets/js/admin/popup-sse.js
한 줄: 관리자 레이아웃에서 팝업 스트림을 엽니다.
받음: popup_created, popup_updated, popup_deleted.
함: EventSource 로 연결하고, 등록된 콜백과 admin:popup:... 이벤트로 넘깁니다.
돌림: window.AdminPopupSSE.
안 함: 표 HTML을 직접 그리지 않습니다.
헷갈림: 레이아웃이 한 번 로드되면 팝업 화면이 아니어도 연결을 유지합니다. 회원·학습 SSE와 같은 방식입니다.
templates/admin/popup_create.html · assets/js/admin/popup-create.js
한 줄: 등록 화면에서 노출일 때 다음 표시 순서를 보여 줍니다.
받음: 상태 선택, GET /admin/popups/next-sort, 팝업 SSE.
함: 노출이면 순서 칸을 읽기 전용으로 두고 다음 번호를 채웁니다. 다른 관리자가 팝업을 바꾸면 그 번호를 다시 불러옵니다. 숨김이면 0을 넣고 직접 수정할 수 있습니다.
돌림: 순서 입력값.
안 함: 저장 순서를 화면 값만으로 확정하지 않습니다. 노출 등록의 최종 번호는 서버가 저장 직전에 다시 계산합니다.
헷갈림: 화면의 번호와 저장 번호가 잠깐 다를 수 있습니다. 그 사이에 다른 노출 팝업이 등록되면 서버 번호가 하나 더 큽니다.
assets/js/admin/popup-manager.js
한 줄: 팝업 목록 표를 그리고, SSE가 오면 표를 다시 불러옵니다.
받음: #popupTable, SSE 세 이벤트.
함: GET /admin/popups_all 로 행을 채웁니다. 등록·수정·삭제 알림이 오면 열려 있는 표를 다시 조회합니다.
돌림: 표 안의 행.
안 함: 이벤트의 필드만으로 행을 끼워 넣지 않습니다. 항상 목록 API를 다시 부릅니다.
헷갈림: 같은 브라우저에서 삭제한 경우 삭제 응답과 SSE가 둘 다 목록을 다시 부를 수 있습니다. 결과는 같은 목록입니다.
