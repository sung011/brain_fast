학습 문서 목록

흉부 X-ray 분석은 무엇을 하는가

흉부 X-ray 화면의 일부를 받아 어떤 소견일 가능성이 높은지 계산하고, 모델이 주목한 위치를 색으로 표시합니다. 학습용 보조이며 진단이 아닙니다.

지금은 팀의 흉부 모델이 아직 준비되지 않은 상태입니다. .env에 THORAX_HF_REPO와 THORAX_CKPT_FILES를 넣기 전까지 흉부 분석과 흉부 ROI 채점은 "모델 준비 중"(503)을 돌려줍니다.

판독문(MedGemma)은 아직 없습니다. 뇌 CT에만 있습니다.

한 번 요청이 지나가는 순서

  1. 화면 공유 분석 화면에서 부위를 흉부 X-ray로 고르고 네모 박스를 그립니다.
  2. 브라우저가 박스 안 이미지를 POST /api/v1/thorax/analyze/screen-roi로 보냅니다.
  3. routers/thorax.py가 class/thorax/를 불러 전처리 → 분류 → 위치 표시를 차례로 부릅니다.
  4. 응답 형식은 뇌 CT 분석과 같습니다. classification.task가 thorax이고 germinoma는 항상 비어 있습니다.

파일별 역할

class/thorax/config.py

한 줄로
흉부 모델의 위치와 숫자 설정을 환경 변수에서 읽습니다.
받는 것
THORAX_HF_REPO, THORAX_CKPT_FILES(쉼표로 여러 개), THORAX_IMG_SIZE, THORAX_HIGH_PROB_THR.
하는 것
값을 읽고, 모델 위치가 정해졌는지(model_configured()) 알려 줍니다.
돌려주는 것
다른 파일이 쓰는 설정값.
하지 않는 일
DB·NAS 설정은 다루지 않습니다. 그건 루트 config.py입니다.
헷갈리기 쉬운 점
뇌 CT의 HF_REPO와 이름이 다릅니다. 흉부는 앞에 THORAX_가 붙습니다.

class/thorax/constants.py

한 줄로
소견 이름의 순서와 화면에 보일 이름, overlay 색을 둡니다.
받는 것
없음. 고정 목록입니다.
하는 것
class_label(이름, 언어)로 표시 이름을 찾습니다. 지금은 한국어(ko)와 영어(en)가 있습니다.
돌려주는 것
표시 이름. 그 언어가 없으면 한국어, 한국어도 없으면 원래 영어 이름.
하지 않는 일
모델 출력 순서를 정하지 않습니다. 체크포인트에 classes 목록이 있으면 그 순서가 이깁니다.
헷갈리기 쉬운 점
기본 목록(VinDr-CXR 14개)은 잠정입니다. 팀 모델의 클래스가 정해지면 체크포인트의 순서를 따릅니다. 다국어를 붙일 때는 LABELS에 언어 코드를 추가하면 됩니다.

class/thorax/preprocess.py

한 줄로
업로드 파일을 모델이 먹는 흑백 3채널 이미지로 바꿉니다.
받는 것
PNG·JPG·DICOM 바이트와 파일 이름.
하는 것
흑백으로 바꿔 3번 복제합니다. DICOM은 밝기 범위를 맞추고, 흰 배경 형식(MONOCHROME1)은 반전합니다.
돌려주는 것
세로×가로×3 크기의 0~255 배열.
하지 않는 일
CT처럼 HU 윈도우를 쓰지 않습니다. X-ray에는 HU가 없습니다.
헷갈리기 쉬운 점
MONOCHROME1을 반전하지 않으면 뼈가 검게 보여 모델이 엉뚱하게 판단합니다.

class/thorax/ensemble.py

한 줄로
Hugging Face에서 흉부 모델들을 받아 소견별 확률을 계산합니다.
받는 것
전처리된 이미지 배열.
하는 것
모델마다 sigmoid 확률을 구해 평균합니다. 한 영상에 소견이 여러 개일 수 있어서(다중 라벨) 확률을 더해 1이 되지 않습니다.
돌려주는 것
클래스 순서대로 0~1 확률 배열.
하지 않는 일
설정이 비어 있으면 모델을 받지 않고 "모델 준비 중" 오류를 냅니다. 체크포인트 파일을 저장소에 넣지 않습니다.
헷갈리기 쉬운 점
체크포인트 출력 수와 클래스 수가 다르면 바로 오류를 냅니다. 순서가 어긋난 채로 엉뚱한 이름을 보여 주는 것보다 낫기 때문입니다.

class/thorax/localization.py

한 줄로
모델이 어디를 보고 판단했는지(Grad-CAM) 색으로 칠합니다.
받는 것
앙상블, 이미지, 확률.
하는 것
확률이 기준(기본 0.5) 이상인 소견마다, 없으면 가장 높은 소견 1개에 대해 Grad-CAM을 구합니다. 검은 여백과 가장자리 글자를 뺀 영역에서 강한 부분을 마스크로 만듭니다.
돌려주는 것
소견별 마스크, overlay PNG, 한 줄 요약(예: "기흉 (p=0.82, 상부-환자 우측)").
하지 않는 일
뇌 CT처럼 밝기로 출혈을 찾는 단계는 없습니다.
헷갈리기 쉬운 점
흉부 PA 영상은 화면 왼쪽이 환자의 오른쪽입니다. 요약의 좌우는 환자 기준입니다. Grad-CAM은 모델이 주목한 곳이지 병변의 정확한 경계가 아닙니다.

routers/thorax.py

한 줄로
흉부 분석 주소를 열고 class/thorax/를 부릅니다.
받는 것
GET /api/v1/thorax/health, POST /api/v1/thorax/analyze/screen-roi(image, modality, include_overlay).
하는 것
크기(최대 5MB)를 확인하고 분석한 뒤 뇌 CT와 같은 형식으로 응답합니다. NAS_UPLOAD_ON_ANALYZE가 켜져 있으면 NAS에도 올립니다.
돌려주는 것
분류 결과, overlay, 요약, 면책 문구.
하지 않는 일
판독문(/explain)은 없습니다.
헷갈리기 쉬운 점
뇌 CT 주소는 /api/v1/analyze/..., 흉부는 가운데에 /thorax가 들어갑니다.

ROI 채점에서 달라진 점

  • POST /learning/roi-grade는 이제 문제의 부위를 봅니다. study_idx가 있으면 그 문제의 st_part·st_modal을, 없으면 폼으로 받은 값을 씁니다.
  • 흉부(st_part=2) X-ray면 흉부 모델로, 그 밖에는 예전처럼 뇌 CT 모델로 채점합니다.
  • 흉부 CT·MRI는 흉부 X-ray 모델로 채점하지 않고 400을 돌려줍니다.
  • 정답·부분정답·오답 기준(겹침 정도)과 응답 모양은 뇌 CT와 같습니다. 자세한 기준은 학습 ROI 채점에 있습니다.

모델이 준비되면 할 일

  1. 체크포인트에 classes(학습 때 순서)와 model_name(timm 이름)을 넣어 Hugging Face에 올립니다.
  2. .env에 THORAX_HF_REPO, THORAX_CKPT_FILES를 적습니다.
  3. 학습 때 입력 크기·정규화가 다르면 THORAX_IMG_SIZE와 ensemble.py의 전처리를 맞춥니다.
  4. GET /api/v1/thorax/health로 로드 상태를 확인합니다.

검증

pytest tests/test_thorax.py는 무작위로 만든 가짜 모델로 전처리, 다국어 이름, 설정 누락 시 503, 응답 형식, ROI 채점 분기를 확인합니다. 가짜 모델이라 확률 값 자체는 의미가 없습니다. torch가 없는 환경에서는 건너뜁니다.
