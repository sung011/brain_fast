흉부 X-ray 분석은 무엇을 하는가

흉부 X-ray 화면의 일부를 받아, 소견마다 따로 있는 탐지 모델로 이상 부위를 네모 박스로 찾고 색으로 표시합니다. 학습용 보조이며 진단이 아닙니다.

지금 연결할 수 있는 모델은 폐음영(mediscan_opacity_detector_v2)과 흉막삼출(mediscan_effusion_detector_v2_3) 두 가지와, 2026-10-20에 추가한 기흉(mediscan_pneumothorax_detector_v2, SIIM+VinDr 학습, 기준값 0.125)입니다. 기흉은 NIH 다른 병원 사진 20장을 모두 찾았지만 위치는 대략적입니다(겹침 0.3 이상 11/20). 심비대(mediscan_cardiomegaly_detector_v1, VinDr 학습, 기준값 0.35)는 2026-10-21에 추가했습니다. NIH 심비대 사진 20장 중 18장을 찾았지만, 누워서 찍은(AP) 사진은 심장이 크게 보여 정상 사진도 심비대로 표시하는 일이 많습니다. NIH 정상 AP 사진을 학습에 더해 봤더니 헛짚기는 줄었지만 진짜 심비대도 거의 못 찾게 되어(모델이 "NIH AP 사진은 정상"이라는 지름길을 배움) 처음 모델을 쓰고, 해설에 AP 사진의 한계를 적었습니다.

흉막삼출은 v2.1 대신 v2.3을 씁니다. PadChest 독립 테스트 913장에서 위양성이 130개에서 89개로 줄었고(놓친 병변은 7개에서 8개), AUROC는 0.86에서 0.94로 올랐습니다. 매우 큰 흉막삼출을 놓칠 수 있는 약점은 남아 있습니다.

.env에 THORAX_PACKAGES와 THORAX_HF_REPO(개발 중에는 THORAX_LOCAL_DIR)를 넣기 전까지 흉부 분석과 흉부 ROI 채점은 "모델 준비 중"(503)을 돌려줍니다. 판독문(MedGemma)은 아직 없습니다.

모델 패키지란

소견 하나당 폴더 하나입니다. 안에 가중치 best.pt와 설정 inference_config.json이 있습니다. 설정에는 소견 이름, 입력 크기, 판정 기준값(confidence), 겹친 박스 정리 기준(NMS), 최대 박스 수가 들어 있습니다. 선택으로 minimum_area_ratio(이미지 면적 대비 이보다 작은 박스는 버림)를 넣을 수 있습니다. 서버는 이 값을 그대로 씁니다.

한 번 요청이 지나가는 순서

  1. 화면 공유 분석 화면에서 부위를 흉부 X-ray로 고르고 네모 박스를 그립니다.
  2. 브라우저가 박스 안 이미지를 POST /api/v1/thorax/analyze/screen-roi로 보냅니다.
  3. routers/thorax.py가 class/thorax/를 불러 전처리 → 소견별 탐지 → 박스 표시를 차례로 부릅니다.
  4. 응답 형식은 뇌 CT 분석과 같습니다. classification.task가 thorax이고, 소견 점수는 그 소견 박스의 가장 높은 신뢰도입니다.

class/thorax/preprocess.py

업로드 파일을 모델이 먹는 흑백 3채널 이미지로 바꿉니다.

PNG·JPG·DICOM 바이트와 파일 이름.

class/thorax/ensemble.py

한 줄로
소견별 탐지 모델을 모두 돌려 박스를 모읍니다.
받는 것
전처리된 이미지 배열.
하는 것
패키지마다 설정 파일의 입력 크기·기준값으로 YOLO 추론을 하고, 박스(소견, 신뢰도, 좌표)를 모읍니다. 소견 점수는 그 소견 박스의 최고 신뢰도입니다.
돌려주는 것
박스 목록과 소견별 점수.
하지 않는 일
모델 파일 안에 저장된 이름을 믿지 않습니다. 흉막삼출 모델은 파일 안 이름이 item이라, 설정 파일의 이름을 씁니다.
헷갈리기 쉬운 점
기준값이 0.05 정도로 낮게 잡혀 있습니다. 점수 0.3도 "찾았다"는 뜻입니다. 확률(%)로 읽으면 안 됩니다.

class/thorax/localization.py

한 줄로
찾은 박스를 색칠하고 위치를 한 줄로 요약합니다.
받는 것
박스 목록과 이미지.
하는 것
먼저 같은 소견에서 겹치는 박스를 감싸는 박스 하나로 합치고, 소견마다 점수 높은 2곳만 남깁니다(merge_regions). 그다음 박스 안을 소견 색으로 옅게 칠하고 테두리를 그립니다. 남은 박스를 합친 마스크가 ROI 채점의 "이상 부위"가 됩니다.
돌려주는 것
소견별 마스크, overlay PNG, 요약(예: "흉막삼출: 하부-환자 우측 0.28, 중부-환자 좌측 0.08"). 요약은 박스마다 위치와 신뢰도를 적습니다. 위양성 박스가 진짜 병변보다 점수가 높을 수 있어서 하나만 고르지 않습니다.
하지 않는 일
뇌 CT처럼 Grad-CAM으로 위치를 추정하지 않습니다. 모델이 준 박스를 그대로 씁니다.
헷갈리기 쉬운 점
흉부 PA 영상은 화면 왼쪽이 환자의 오른쪽입니다. 요약의 좌우는 환자 기준입니다.
왜 합치나
모델이 같은 자리에 박스를 여러 개 내서(예: 폐음영 박스 5개 중 4개가 겹침) 화면이 어지러웠습니다. 2곳까지 남기는 이유는 양쪽 폐에 하나씩 있을 수 있고, 점수가 더 높은 박스가 위양성일 수도 있기 때문입니다. 채점도 화면에 보이는 영역으로만 하므로, 안 보이는 박스 덕분에 정답이 되는 일은 없습니다. 대신 합친 박스는 원래 박스들보다 조금 넓습니다.

한 줄로

헷갈리기 쉬운 점
의학 내용 검토자가 없어 교과서 수준의 일반 내용만 넣었고, 모든 문장은 "~와 관련될 수 있습니다"처럼 단정하지 않습니다. 글을 고칠 때는 이 파일만 고치면 됩니다. 지금은 폐음영·흉막삼출·기흉·심비대 4개입니다.

ROI 채점에서 달라진 점

  • POST /learning/roi-grade는 이제 문제의 부위를 봅니다. study_idx가 있으면 그 문제의 st_part·st_modal을, 없으면 폼으로 받은 값을 씁니다.
  • 흉부(st_part=2) X-ray면 흉부 모델로, 그 밖에는 예전처럼 뇌 CT 모델로 채점합니다.
  • 흉부 CT·MRI는 흉부 X-ray 모델로 채점하지 않고 400을 돌려줍니다.
  • 흉부는 의심 부위마다 따로 채점합니다(grade_regions). 학습자는 ROI를 여러 개 보낼 수 있고(rois, JSON 배열, 최대 10개, 형식은 schemas/roiGradeSchemas.py), 모든 의심 부위를 찾으면 정답, 일부만 찾거나 근처면 부분정답, 아니면 오답입니다. 다 찾았어도 그린 범위의 25% 미만만 의심 부위면 "너무 넓게 그림"으로 부분정답입니다. 겹치는 다른 소견 박스는 한 부위로 봅니다. 응답에 targets, target_count, found_count, too_wide가 더 붙습니다. 헷갈리기 쉬운 점: 예전처럼 부위를 하나로 합쳐 비교하면 두 부위 사이(아무것도 없는 곳)가 '가깝다'고 판정됐습니다.
  • 정답·부분정답·오답 기준값(IoU·재현율)과 응답 모양은 뇌 CT와 같습니다. 자세한 기준은 학습 ROI 채점에 있습니다.

새 소견 모델을 붙이는 방법

  1. 패키지 폴더(best.pt + inference_config.json)를 Hugging Face 저장소에 폴더째 올립니다.
  2. .env의 THORAX_PACKAGES에 폴더 이름을 쉼표로 추가합니다.
  3. 새 소견이면 constants.py의 CLASSES·LABELS·CLASS_COLORS에 한 줄씩 넣습니다.
  4. GET /api/v1/thorax/health로 로드 상태를 확인합니다.

헷갈리기 쉬운 점 (채점)

흉부 ROI 채점의 "정답 위치"는 모델이 찾은 박스입니다. 모델이 병변을 놓치면 학습자가 맞게 그려도 오답이 됩니다. 데이터셋의 정답 박스로 채점하는 방식은 팀이 정하면 따로 추가합니다.

검증

pytest tests/test_thorax.py는 정해진 박스를 돌려주는 가짜 모델로 설정값 전달, 이름 변환, 503, 응답 형식, ROI 채점을 확인합니다. torch·ultralytics가 없어도 돌아갑니다. THORAX_TEST_LOCAL_DIR에 실제 패키지 폴더를 주면 실제 모델을 불러와 한 번 돌려 봅니다.
