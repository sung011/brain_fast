이미지 저장

스터디, 팝업, 채점 이미지와 분석 결과 파일을 네이버 클라우드 Object Storage 버킷에 올립니다. 화면의 이미지는 학습용 보조이며 진단이 아닙니다.

데이터베이스에는 /stylesheets/assets/... 같은 웹 경로만 저장합니다. 브라우저 주소는 NAS_PUBLIC_BASE_URL 뒤에 그 경로를 붙입니다.

파일마다 보기

services/objectStorageServices.py
한 줄: 버킷에 파일을 올리고 웹 경로를 돌려줍니다.
받음: 파일 바이트, 파일 이름, 저장 폴더(/stylesheets/assets, review, popup).
함: 한국 리전 S3 호환 API로 객체를 넣고, 화면에서 열 수 있게 공개 읽기를 붙입니다. 예전 /web/mu_shop/public 접두어는 객체 키에서 뺍니다.
돌림: 웹 경로, 객체 키, 바이트 수. 분석 묶음이면 원본·overlay·result.json 목록.
안 함: 회원 로그인, 채점, DB 저장. 키 값을 로그에 남기지 않습니다.
헷갈림: 버킷 목록 공개와 파일 공개는 다릅니다. 코드는 올린 파일만 공개합니다.
config.py · .env
한 줄: 버킷 이름, 엔드포인트, 공개 주소, 폴더 경로를 읽습니다.
받음: NCP_ACCESS_KEY, NCP_SECRET_KEY, NCP_BUCKET, NAS_PUBLIC_BASE_URL.
함: 값이 없으면 업로드를 비활성으로 둡니다.
돌림: settings 객체.
안 함: 키 값을 코드에 적지 않습니다.
헷갈림: 폴더 설정 이름이 NAS_로 남아 있어도 저장 위치는 Object Storage입니다.
routers/admin.py · services/reviewNodeServices.py · routers/brain.py
한 줄: 스터디·팝업·채점·분석 결과 업로드가 이 저장소를 호출합니다.
받음: 관리자 등록 파일, 학습 제출 이미지, 분석이 만든 overlay.
함: 올린 뒤 DB에는 웹 경로만 넣습니다. NAS_UPLOAD_ON_ANALYZE가 켜져 있으면 분석 파일도 같은 버킷에 올립니다.
돌림: 저장된 경로. 설정이 없으면 503, 업로드 실패면 502.
안 함: 이미 버킷에 없는 예전 파일을 복사하지 않습니다.
헷갈림: 예전에 NAS에만 있던 이미지는 이 주소로 열리지 않습니다. 다시 등록해야 합니다.
