학습 문서 목록

학습 ROI 채점은 무엇을 하는가

POST /learning/roi-grade는 학습자가 그린 박스/원과 이미지의 이상 부위가 겹치는지 보고 정답·부분정답·오답을 냅니다. 의사 진단이 아닙니다.

결과는 학습용 보조입니다. MRI는 슬라이스가 여러 장이라 어느 장에 ROI를 그렸는지 서버가 알아야 합니다.

한 번 요청이 지나가는 순서

  1. 프론트가 현재 보이는 장 PNG와 ROI 좌표, study_idx를 보냅니다.
  2. MRI면 추가로 slice_index(0부터) 또는 image_path로 슬라이스를 지정합니다.
  3. routers/commonness.py가 슬라이스를 맞춘 뒤 services/roiGradeServices.py로 채점합니다.
  4. 제출 이미지를 Object Storage /stylesheets/assets/review에 올리고 review_node에 이력을 남깁니다. rn_disease에는 문제 정답이 아니라, 출혈·생식세포종양 확률 중 가장 높은 병명이 들어갑니다.
  5. 응답은 기존과 같습니다(ok, 판정, overlay 등). 다음 문제가 있으면 next도 붙습니다.

routers/commonness.py — /learning/roi-grade

한 줄
multipart 폼으로 이미지·ROI·(MRI)슬라이스 정보를 받아 채점 서비스에 넘깁니다.
받는 것
image, roi_type, 좌표, study_idx, optional slice_index·image_path, user_idx, st_part/st_modal.
하는 일
MRI 슬라이드 문제면 learningServices.resolve_roi_grade_slice로 배열 항목을 고릅니다. 없거나 범위 밖이면 400과 한글 detail을 돌립니다. 그다음 기존처럼 채점·리뷰 저장합니다.
돌려주는 것
기존과 동일: ok, result, IoU·overlay, 리뷰 경로, next.
하지 않는 일
슬라이스별 정답 ROI 좌표를 DB에서 꺼내지 않습니다. 채점 GT는 올린 이미지에 대한 모델 localization입니다.
헷갈리기 쉬운 점
OpenAPI(/docs, /openapi.json)에 Form 필드로 자동 반영됩니다. CT 클라이언트는 새 필드를 안 보내도 됩니다.

services/learningServices.py — 슬라이스 고르기

한 줄
study.st_image가 JSON 배열일 때 제출 슬라이스를 고릅니다.
받는 것
study_idx, optional slice_index(0-based), optional image_path.
하는 일
slice_index는 배열 순번과 맞춥니다. image_path는 전체 경로 또는 파일명으로 맞춥니다. 둘 다 있으면 같은 장을 가리켜야 합니다.
돌려주는 것
고른 slice_index, image_path, 전체 장 수. CT/단일 영상이면 None.
하지 않는 일
이미지를 다시 받지 않습니다. ROI 겹침 계산도 하지 않습니다.
헷갈리기 쉬운 점
DB에 슬라이스별 GT ROI 박스는 없습니다. MRI GT “슬라이스”는 st_image 배열 항목이고, 채점용 이상 마스크는 제출 이미지에서 만듭니다.

services/roiGradeServices.py — 겹침 채점

한 줄
올린 이미지에서 이상 부위를 찾고 사용자 ROI와 겹침으로 판정합니다.
받는 것
이미지 바이트와 박스/원 좌표.
하는 일
뇌 앙상블·localization으로 GT 마스크를 만들고 IoU·재현율로 정답/부분정답/오답을 냅니다.
돌려주는 것
판정, 점수, overlay PNG(base64), 사용자/이상 bbox.
하지 않는 일
study_idx·슬라이스 필드를 읽지 않습니다. 슬라이스 검증은 라우터·learning 서비스가 합니다.
헷갈리기 쉬운 점
프론트가 보이는 장 파일을 image로 보내야 좌표와 픽셀이 맞습니다.

흉부 X-ray — 의심 부위별 채점 (grade_regions)

한 줄
흉부는 의심 부위가 여러 곳일 수 있어, 부위마다 학습자 ROI가 찾았는지 따로 봅니다.
받는 것
폼 값 rois: ROI 여러 개를 담은 JSON 배열(최대 10개). 형식 검사는 schemas/roiGradeSchemas.py의 parse_rois가 하고, 틀리면 400입니다. 없으면 예전처럼 roi_type·좌표 한 개로 채점합니다.
하는 일
탐지 박스 중 겹치는 것(다른 소견이어도)을 한 부위로 묶고, 부위마다 가장 잘 맞는 ROI의 IoU·재현율을 봅니다. 모두 찾으면 정답, 일부만 찾거나 근처면 부분정답, 아니면 오답입니다. 다 찾았어도 그린 범위 중 의심 부위가 25%(MIN_PRECISION)보다 적으면 "너무 넓게 그림"으로 부분정답입니다.
돌려주는 것
기존 응답에 targets(부위별 좌표·소견·찾음 여부), target_count, found_count, too_wide가 더 붙습니다.
하지 않는 일
뇌 CT 채점은 바꾸지 않았습니다. 뇌는 rois를 보지 않고 마지막 ROI 하나로 채점합니다.
의심 부위는 어디서 오나
문제에 데이터셋 정답 박스가 있으면(learningServices.get_answer_boxes) 그 박스가 의심 부위이고 응답의 target_source는 dataset입니다. 이때 overlay는 정답 박스를 그리고, AI가 찾은 부위는 overlay_summary에 "AI 참고 — …"로 적고, 사진에는 파란 테두리로만 덧그리며(신뢰도 높은 순 최대 3곳), 응답의 ai_targets(0~1 비율 좌표·신뢰도·소견)로도 돌려줍니다. 채점에는 쓰지 않습니다. 정답 박스가 없으면 예전처럼 AI 박스가 의심 부위이고 target_source는 ai입니다. study 테이블에 정답 박스 칸이 아직 없어서(팀 결정 전) 실제 서버에서는 늘 ai입니다.
맞은 정도 숫자 한 줄
채점 응답의 metrics_text는 "내 영역이 정답 부위의 42%를 덮었고, 내 영역 중 30%가 정답 부위 안에 있어요."처럼 숫자만 말하는 한 문장입니다. 앞 숫자는 recall(기준 부위 중 내 영역이 덮은 비율), 뒤 숫자는 precision(내 영역 중 기준 부위 안에 있는 비율)이고 둘 다 이미 계산돼 있던 값입니다. 채점 기준이 AI(target_source: "ai")이면 "정답 부위" 대신 "AI가 찾은 부위"라고 씁니다. 정답·부분정답·오답 판정은 바꾸지 않고, "많이·거의" 같은 평가도 붙이지 않습니다. 그리지 않았거나 기준 부위가 없거나 값이 이상하면 빈 문자열이고, 화면은 빈 문자열이면 아무것도 보여 주지 않습니다.
틀린 이유 문장
응답의 feedback은 정답 부위를 못 찾았을 때 이유를 쉬운 말로 알려 주는 문장 목록입니다(roi_feedback). 반대쪽 폐를 골랐는지, 위치는 맞는데 작게 그렸는지, 거의 맞았는지, 다른 곳을 골랐는지를 구분합니다. 최종 판정(result)이 오답이면 겹침이 조금 있어도 "거의 맞았어요"라고 하지 않고 "일부 겹쳤지만 정답 기준에는 못 미쳤어요. 정답은 조금 더 ○○에 있어요."라고 말합니다. 판정과 문장이 서로 다른 말을 하지 않게 하려는 것이며, 판정 기준(IoU·재현율)은 바꾸지 않았습니다. 411문제를 합성 제출로 채점해 보다가 이 충돌이 한 번 나와 고쳤습니다.
학습 해설
흉부 문제는 정답(소견)으로 고른 해설을 learning_note에 함께 돌려줍니다. 흉부 정답은 병명이 아니라 영상 소견이라 kind가 finding이고, 화면은 "정답 소견"·"소견 해설"로 씁니다. 순서는 이 소견은 → 판독 포인트 → 이 영상에서는(채점한 의심 부위의 위치·개수·크기로 만든 문장) → 감별할 질환 → 확인하려면(확인 검사) → 다른 소견과 같이 보이면 → 헷갈리기 쉬운 점입니다. 제출한 뒤라 정답을 보여 줘도 됩니다. 뇌는 아직 없어서 null입니다. 해설은 services/learningNoteServices.py 한 곳에서 고르며, 팀장님이 만드는 의학용어 사전(RAG)이 준비되면 그 파일의 _from_rag()만 채우면 됩니다. RAG 결과가 있으면 그걸 먼저 쓰고(source: "rag"), 없으면 흉부 고정 해설을 씁니다(source: "static"). 돌려줄 모양은 그 파일 맨 위에 적어 두었습니다. 서버 .env에 GLOSSARY_CSV_PATH(팀 RAG 자료의 의학용어 사전 CSV)가 있으면, "이 소견은" 정의만 그 사전의 한글 정의로 바꿉니다(영문 이름이 정확히 같은 행, 두 문장까지, summary_source: "glossary"). 사전에는 판독 포인트·헷갈리기 쉬운 점이 없어서 나머지 칸은 고정 글 그대로입니다. 채점 overlay의 의심 부위는 소견 구분 없이 화면 범례와 같은 청록색 한 가지로 그립니다.
헷갈리기 쉬운 점
예전처럼 부위들을 한 덩어리로 합쳐 비교하면, 두 부위의 중심이 그 사이(아무것도 없는 곳)가 되어 거기를 그려도 부분정답이 났고, 가슴 전체를 크게 그리면 정답이 났습니다. 결과는 학습용 보조이며 진단이 아닙니다.

학습자 화면(Vue)이 함께 쓰는 API

GET /learning/problem/{번호}/image

한 줄로
문제 영상 한 장을 NAS에서 서버가 대신 받아 돌려줍니다.
받는 것
문제 번호, slice_index(MRI만, 0부터).
하는 것
study 행의 st_image로 NAS 공개 주소를 만들어 영상을 받습니다.
돌려주는 것
영상 바이트. 없는 문제·삭제된 문제 404, 범위 밖 슬라이스·지원하지 않는 형식 400, NAS 실패 502.
하지 않는 일
요청으로 받은 임의 주소를 열지 않습니다. 주소는 DB의 study 행으로만 만듭니다.
헷갈리기 쉬운 점
브라우저가 NAS에서 직접 받으면 다른 출처(CORS) 때문에 그 영상을 채점 API로 다시 보내지 못할 수 있습니다. 배포한 Vue 화면은 개발용 프록시가 없으므로 이 주소를 씁니다. 한글 파일 이름은 응답 헤더에 RFC 5987 형식으로 넣습니다.

한 줄로
제출한 뒤에만 정답 병명(study.st_disease)을 돌려줍니다.
헷갈리기 쉬운 점
문제를 받을 때(/learning/problem)는 정답을 숨기고, 채점 응답에서만 보여 줍니다.
