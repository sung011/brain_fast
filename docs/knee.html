무릎 MRI 분석은 무엇을 하는가

무릎 MRI 볼륨(슬라이스 묶음)을 받아 “이상 소견”, “ACL(전방십자인대)”, “반월판” 세 가지를 숫자로 추정하고, ACL이 있는 대략적인 위치를 박스로, 모델이 참고한 영역을 색으로 보여 줍니다. 의사 진단이 아닙니다.

결과는 학습·실습용 보조입니다. 박스는 “ACL이 있는 대략적 해부학 위치”이고 파열 위치가 아닙니다. 색 영역은 모델이 참고한 곳이지 병변이 아닙니다. 숫자는 보정된 모델 점수이지 개인의 실제 위험률이 아닙니다.

이 패키지는 아직 API 주소에 연결되어 있지 않습니다. 코드로만 불러 쓸 수 있고, 주소·응답 형식은 설계 후에 붙입니다.

한 번 예측이 지나가는 순서

  1. 호출하는 쪽이 촬영면별 볼륨을 {"axial": ..., "coronal": ..., "sagittal": ...} 모양으로 넘깁니다. 일부 면만 있어도 됩니다.
  2. preprocess.py가 볼륨이 (슬라이스, 높이, 너비) 숫자 배열인지, NaN·너무 큰 크기가 아닌지 확인합니다. 이상하면 여기서 멈춥니다.
  3. ensemble.py가 소견마다 필요한 촬영면 모델로 확률을 구해 평균하고 보정합니다.
  4. 보정된 확률이 0.4~0.6 사이면 “판단 어려움”, 아니면 “가능성 높음/낮음”으로 문구를 정합니다.
  5. 필요하면 localization.py가 ACL 박스와 Grad-CAM 색 영역을 만듭니다.

class/knee/config.py — 설정

한 줄
가중치를 어디서 받을지, 어떤 파일을 쓸지, 입력 크기 한도가 얼마인지 정해 둡니다.
받는 것
환경 변수 또는 프로젝트 .env의 KNEE_HF_REPO(저장소), KNEE_HF_REVISION(선택, 고정할 커밋).
하는 일
값을 “환경 변수 → .env → 기본값” 순서로 찾습니다. 부를 때마다 읽어서, .env를 나중에 바꿔도 반영됩니다.
돌려주는 것
저장소 이름, 소견×촬영면별 체크포인트 파일 이름, 게이팅 구간, 크기 한도.
하지 않는 일
가중치 파일을 저장소에 두지 않고, 토큰 같은 비밀값을 적지 않습니다. 입력 크기(224)는 학습 값 그대로라 바꿀 수 없게 두었습니다.
헷갈리기 쉬운 점
팀원마다 저장소 계정이 달라도 각자 .env에 자기 값을 적으면 됩니다. 반월판은 결합기가 axial·coronal만 쓰도록 골랐기 때문에 sagittal 모델을 올리지 않았습니다.

class/knee/preprocess.py — 전처리

한 줄
영상을 모델이 읽는 크기와 밝기로 맞춥니다.
받는 것
(슬라이스, 높이, 너비) 숫자 배열 하나.
하는 일
먼저 배열 모양·자료형·NaN·크기 한도를 검사합니다. 통과하면 밝기를 0~1로 맞추고, 필요하면 가운데를 잘라 224×224로 줄인 뒤 3채널로 만들어 ImageNet 방식으로 정규화합니다.
돌려주는 것
(슬라이스, 3, 224, 224) 텐서.
하지 않는 일
DICOM 읽기, 촬영면 추측, 영상 저장은 하지 않습니다.
헷갈리기 쉬운 점
슬라이스가 여러 장이라 모양이 정확히 3차원이어야 합니다. 한 장짜리 2차원 그림은 받지 않습니다.

class/knee/model.py — 모델 구조

한 줄
슬라이스별 ResNet 특징을 하나로 합쳐 점수 하나를 내는 구조입니다.
받는 것
(슬라이스, 3, 224, 224) 텐서.
하는 일
슬라이스를 각각 ResNet에 통과시킨 뒤, 가장 이상한 슬라이스를 대표로 잡거나(max) 중요한 슬라이스에 더 가중치를 주어(attention) 합칩니다.
돌려주는 것
확률로 바꾸기 전 점수 하나(logit).
하지 않는 일
학습하지 않습니다. 이미 학습된 가중치를 받아 예측만 합니다.
헷갈리기 쉬운 점
층 이름(features, attn, head)이 학습 때와 같아야 가중치가 들어갑니다. 예측과 Grad-CAM이 같은 모델 객체를 동시에 쓰지 않도록 INFERENCE_LOCK도 여기 있습니다.

class/knee/ensemble.py — 앙상블

한 줄
가중치를 받아 오고, 촬영면별 예측을 합쳐 소견별 결과를 만듭니다.
받는 것
촬영면 이름을 키로 한 볼륨 묶음. 예: {"sagittal": 볼륨}.
하는 일
처음 부를 때 load()로 Hugging Face에서 파일 17개를 받아 모델 14개를 올립니다. 예측 때는 소견마다 필요한 촬영면의 확률을 평균하고, 보정한 뒤, 0.4~0.6이면 “판단 어려움”으로 표시합니다. 판정은 반올림 전 값으로 하고, 보여 주는 prob만 소수 셋째 자리로 반올림합니다.
돌려주는 것
소견마다 status가 evaluated이면 확률·문구·쓴 면·빠진 면, not_evaluated이면 이유와 필요한 면.
하지 않는 일
필요한 촬영면이 없을 때 낮은 확률로 채우지 않습니다. NaN이나 범위 밖 확률은 결과로 내지 않고 오류를 냅니다.
헷갈리기 쉬운 점
반월판은 axial·coronal만 씁니다. sagittal만 넣으면 반월판은 “판단하지 않음”으로 나옵니다. 학습 폴더의 원본 코드는 이때 sagittal 모델로 대신 답했지만, 성능이 낮아 뺀 것이므로 의도한 차이입니다.

class/knee/localization.py — 위치 표시

한 줄
ACL이 있는 대략적 위치 박스와, 모델이 참고한 영역 색칠을 만듭니다.
받는 것
슬라이스 한 장(0~1 회색), 또는 볼륨과 모델.
하는 일
YOLO 모델로 박스를 찾고, Grad-CAM으로 어디를 참고했는지 계산해 가장 강한 한 덩어리만 옅게 칠합니다. 최댓값의 5%보다 큰 반응만 칠하기 때문에, 반응이 한 점뿐인 CAM에서도 반응 없는 영역까지 칠하지 않습니다. 계산 도중 실패해도 걸어 둔 감시 장치(hook)를 반드시 뗍니다.
돌려주는 것
박스(0~1 비율 좌표, 못 찾으면 None), 색칠한 이미지와 “색칠했는지” 여부.
하지 않는 일
병변(파열) 위치를 알려 주지 않습니다. 반응이 없는 CAM에는 색칠하지 않고 원본을 그대로 돌려줍니다.
헷갈리기 쉬운 점
박스가 None인 것은 오류가 아니라 “못 찾았다”는 정상 결과입니다. 호출하는 쪽이 이 경우를 처리해야 합니다.
